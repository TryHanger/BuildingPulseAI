# BuildingPulse AI — независимый аудит G5.3

Дата: 2026-11-07. Предмет: `BUILDINGPULSE_G5_3_GATE_REVIEW.zip` и `BUILDINGPULSE_G5_3_G36_1WK_SOURCE_BYTES.zip`, плюс ранее принятый комплект исходных G36-5wk/1wk fault probe. Оригинальный проект не изменён.

## Решение

- **ACCEPT_DESCRIPTIVE_CROSS_FAULT**: G36-5wk, правило `g36-sat-high@1.0.0` (BASIC), четыре прогона; подтверждена воспроизводимость описательных показателей, не причинная локализация и не независимая валидация.
- **STOP_PAIRED_CAUSAL**: сохранить. Общая сетка времени и паспортное намерение одинакового внешнего forcing недостаточны, если фактические зарегистрированные каналы и условия применимости не полностью согласованы.
- **G36-1wk STOP для прежнего протокола `PRE_G36_1WK_SCORE_FREEZE`**: обоснован, агент не должен обходить заранее объявленный gate.
- **GO на новый отдельно зафиксированный однопрогонный описательный тест 1wk** после новой preregistration. Для *unpaired* исследования 100% побайтовое совпадение записанных погодных каналов между baseline и fault не является условием применимости, если правило оценивает каждый прогон независимо; оно необходимо для гораздо более сильных парных претензий. Это не ретроактивное исправление G5.3 и не научная внешняя валидация.

## Независимо воспроизведено

- ZIP CRC: PASS; SHA256SUMS: 64/64 файлов первого архива и 3/3 второго; SHA256 G36-5wk четырёх CSV и G36-1wk baseline/fault probe соответствует квитанциям.
- Четыре CSV G36-5wk: каждый 10081 отсчёт, 5 минут. Независимый собственный скрипт `/mnt/data/bp_g53_delivery/verify_g53_5wk_local.py` (отдельный расчёт, не библиотека S) получил все 12 period-summary (pre/active/post) совпадающими с `CROSS_SCENARIO_INDEPENDENT_RESULTS.json`.
- Активный период 7920 отсчётов на прогон; BASIC policy: ΔSAT=SAT−SP>2 K, fan=1, cooling command>=0.2, heating command<=0.01, MAT−SP>=2K, подтверждение по >=600 s.

## G36-1wk: что точно известно

- Из официальных G36-1wk CoolingSeason CSV: 10081×114, 60 s, идентичные model seconds.
- Baseline: SHA256 `624e3c4e823e265e98d7c982f8498718b263ab1aff4d3fb4f2eb5ff787d370b3`; Fault: SHA256 `46c3e2833a5baddc7159d4424ad0d9e072d1cda06c10c1a96dfcba12c5f94a59`.
- OAT dry отличается в 3720 отсчётах, максимальная разность 0.149658203125 K, медиана *ненулевой* разницы 0.01266479 K; wet в 3858, макс. 0.0958251953125 K, медиана ненулевой 0.00683594 K. Эти отклонения не доказывают различия исходного погодного файла.
- `fan_status` отличается на 2946 отсчётах: `fan=1` в baseline 5460 раз, fault 8402 раз; SAT setpoint — на 3042 отсчётах; occupancy — на 14 (переходные границы). Причина различий не установлена. Кондиционирование по режиму регулятора после вмешательства само по себе может смещать сравнение.
- Модельный oracle `True Value for AHU Cooling Coil Valve Stuck Position` равен 0 на 10079 отсчётах, 1 на последних двух (`t=18230340`, `t=18230400`). Нет права самостоятельно исправить метки или считать эти два отсчёта доказанным «прекращением вмешательства». Для основного анализа BASIC oracle вообще не нужен.
- **Первичный паспорт 1wk, стр. 10**, утверждает, что авторы *задали одинаковые внешние условия, occupancy load и время суток* для парных baseline/fault. Наблюдаемое побайтовое несовпадение OAT требует выяснить, как именно формировался сигнал AHU outdoor и какую роль играет численная симуляция/округление. Не называть его фактом разных погодных файлов.

## Критические различия постановок

1. **Paired causal**: оценка изменения из-за fault требует сопоставимых внешних условий и доказанного дизайна вмешательства. STOP пока сохраняется.
2. **Unpaired descriptive transport**: зафиксировать одно и то же правило, независимо применить к каждому 1wk прогону, показать своё покрытие, abstentions, residuals и episodes без причинных процентов, чувствительности к классу или статистических CI на зависимых минутах. Не требует побайтового совпадения двух метеосигналов между сценариями.
3. **Field transfer/external validation**: не выполняется, оба прогона получены на одном семействе симуляторов, fault probe уже был просмотрен. Статус `NOT_BLIND`, `SIMULATION_ONLY`.

## Проверки реализации

- Приложенные `overlay/backend/app/services/g36_benchmark.py`, API и React раздельно маркируют BASIC и EXTRA_SIMULATED, source ID, model seconds, PRE/ACTIVE/POST, `cause_status=NOT_ASSESSED`; worker использует только BASIC; дополнительные oracle-значения не входят в предикат.
- В `overlay/frontend/src/pages/G36BenchmarkPage.tsx` таблица четырёх сценариев сохраняет denominator и явное `EXPLORATORY_POST_HOC`.
- Журнал `pytest.log`: **303 passed, 73 warnings**; присутствуют логи build, HTTP, Playwright и Docker smoke. Полный регрессионный прогон в идентичной среде независимо не повторён; независимый расчёт G36 CSV и целостность архивов повторены.
- Полный Docker Compose не запускался (отмечено агентом S). Не выдавать за проверенное.

## Методологические требования на будущее

Нельзя подбирать «допуск» погоды в G5.3 после просмотра расхождений. Вместо этого новый протокол **G5.4** должен заранее исключить paired causal как цель, задать независимые метрики по каждому прогону, не подбирать пороги и явно описать статус двух крайних oracle-значений. Если исследователь всё-таки хочет доказать равенство forcing, это *отдельная* проверка publisher ZIP/Modelica файла, не обязательное условие unpaired descriptive score.

Научный источник: Ghalamsiah et al., Scientific Data (2025/2026 online), DOI scientific article `10.1038/s41597-025-06179-y`, G36 release Figshare `10.6084/m9.figshare.29297999.v3`. В статье указаны одиночные вмешательства, идеализированные симуляционные измерения, отсутствие стохастического шума и упрощённая модель приводов. Инженерный перенос в натурные здания не подтверждён.
