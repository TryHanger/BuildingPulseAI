**Решение:** `G4_PRODUCT_ACCEPTED_NARROW`, `G4_SCIENCE_BLOCKED_BY_DATA`. G4 решает заявленную задачу *показа проверенного диагностического симптома*, воспроизводимого отчёта и расследования на синтетической последовательности. В G4 нет обученной/валидированной гибридной системы, Bayesian Network и «универсального AI» — это правильно ограничено документом агента.

## 3. Найденные замечания

| ID | Приоритет | Обнаружено | Действие |
|---|---|---|---|
| G4-P1-01 | **P1: научная семантика UX** | В `frontend/src/components/SynchronousTelemetryCharts.tsx:486` третья панель называется **«Тепловой баланс (OA / RA / MA)»**. В панели только температуры, не используются массовые расходы, энтальпия или тепловая мощность. Слово «баланс» создаёт ложное впечатление о выполненной физической проверке | Переименовать в «Температуры смешения OA / RA / MA» или «Температурное сравнение воздуховодов». Не обещать «тепловой баланс» без нужных каналов |
| G4-P1-02 | **P1: диагностический смысл** | Для события `cause_state=AMBIGUOUS` и `possible_causes` состоят из **трёх заранее определённых категорий**, а не из валидированного причинного вывода. Код ничего не доказывает о механизме | На UI показать «совместимые объяснения, не установленные причины»; не делать автоматический `fault_type`/модельный confidence. Уровни `DETECTED_SYMPTOM` и `CONFIRMED_CAUSE` строго различать |
| G4-P1-03 | **P1: интерпретация результата** | Статус `NO_SYMPTOMS_ON_EVALUATED_WINDOWS` определяется отсутствием **подтверждённого** эпизода, даже если в окне встречались **неподтверждённые pointwise `VIOLATED`**. Пункты `coverage.violated` есть в ответе, но общая строка без них может вводить в заблуждение | Отдельно и постоянно показывать «неподтверждённые нарушения/отсчёты» и «подтверждённые инциденты»; добавить E2E case 1–10 минут нарушения без подтверждения |
| G4-P2-04 | **P2: удобство** | Главный экран demo 1440×900 перегружен техническими метками и большим количеством недоступных BASIC-каналов, требующих прокрутки | Компактная итоговая карточка над деталями: «что проверено», «что найдено», «неизвестно», «следующее действие»; технические корни и SHA доступны раскрытием. Без подмены смыслов |
| G4-P2-05 | **P2: воспроизводимость зависимостей** | G4 пакет — overlay, без Docker lock для научных сред и без Git ancestry; журнал Compose положительный, но локальная самостоятельная репликация невозможна без RC2/G2/G3 и зависимостей | Продолжать пакет с overlay hash manifest, pinned Python 3.11 и отдельной полной checkpoint-сборкой после крупного этапа. Не присылать >200 МБ каждый раз |

**Не дефекты G4, а осознанные незакрытые ограничения:** нет в BASIC независимого travel/flow, не подтверждены `coi_bias`/`sa_bias`, дубли исходных `oa_bias`/`coi_leakage`, неизвестны эксплуатационные fault onset / ground truth и настоящие измерения энергобаланса. Физическое охлаждение/экономайзер в G2 не доказаны. Эти условия остаются открытыми, G4 не должен их «чинить» догадками.

## 4. Оценка отбора следующих методов

Приложен `G4_NEXT_RULE_READINESS.md`. Его вывод не надо игнорировать:
- **OAT bias через `oat_vs_meteo`: `BLOCKED_BY_DATA`** (нет независимого синхронного внешнего термометра/определённого погодного источника, маркировка `oa_bias` содержит дубли).
- **Valve stuck через stroke tracking: `BLOCKED_BY_DATA`** (BASIC команда, нет подтверждённой физической обратной связи + независимого включения охлаждения; EXTRA — переменная модели, не эквивалент независимого натурного измерения).
- **Damper stuck через travel tracking: `BLOCKED_BY_DATA`** (положение и режим/возбуждение не независимо подтверждены; ECON-признак по MAT не доказывает механику).

**НЕ разрешать агенту сразу программировать ни один из трёх методов.** Это не значит, что методы физически «невозможны» вообще. Это значит, что для заявленного набора и исследовательского утверждения сейчас отсутствуют нужные проверенные доказательства. При появлении независимого source / верифицированной симуляционной роли их можно пересмотреть.

## 5. Критерий приёмки

**G4 PRODUCT: `ACCEPT_NARROW`.** Пользователь проходит реальный read-only workflow на исходных рядах, получает воспроизводимый JSON/HTML и понятную границу между demo и benchmark; эти claims подтверждаются кодом, повторением синтетического расчёта и журналами.

**G4 SCIENCE: `BLOCKED_BY_DATA`.** Ни одна значимая fault-level метрика не верифицирована на независимых эпизодах. Проект технически готов к следующим разработкам, но научная готовность к fault-targeted G5 требует отдельного источникового gate.

**G4 RELEASE:** нельзя объявлять `PRODUCTION_READY`, `SOTA` или `FAULT_CAUSE_VALIDATED`.
