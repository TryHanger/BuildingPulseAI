# STAGE 7 — ТЕХНИЧЕСКИЙ ОТЧЕТ ОБ АРХИТЕКТУРЕ СИСТЕМЫ (PRODUCT ARCHITECTURE REPORT)

- **Версия прототипа:** `v0.7-stage7` (Diploma Demonstration Prototype)
- **Тема выпускной квалификационной работы:** «Разработка интеллектуальной системы анализа данных инженерных систем зданий».
- **Статус системы:** Прототип полностью функционирует локально в нативном веб-стеке (FastAPI + React 18 + Parquet + SQLite), воспроизведены все научные эксперименты и интеграционные тесты.

---

## 1. Назначение и границы программного продукта

Платформа **BuildingPulse AI** представляет собой интеллектуальную веб-систему для мониторинга, контроля качества данных, энергоэффективной диагностики и локализации неисправностей вентиляционных установок зданий (AHU — Air Handling Unit).

### Ключевые возможности:
1. **Телеметрия высокого разрешения:** хранение и быстрый доступ к миллионам минутных отсчетов физических параметров HVAC через колоночный формат Apache Parquet.
2. **Адаптивное серверное прореживание (Min-Max Downsampling):** гарантированное сохранение пиков и локальных экстремумов аномалий при отображении до 1 500 точек на экран браузера.
3. **Физическая мнемосхема AHU:** интерактивная SVG-схема основных узлов (воздуховоды наружного, рециркуляционного, смешанного и приточного воздуха, клапан охлаждения, заслонки, вентилятор) с двусторонней синхронизацией по курсору времени.
4. **Многоуровневая диагностика (Anomaly vs Cause):** строгое архитектурное разделение факта обнаружения невязки теплового режима (детекция аномалии) и установления конкретной физической причины (локализация неисправности).
5. **Слой селективных решений (Decision Layer):** механизм подавления ложных диагнозов на основе физических свидетельств приводов и теплового баланса с возможностью контролируемого отказа от неуверенной классификации (`CAUSE_UNRESOLVED`).
6. **Анализ профилей наблюдаемости и рекомендатель каналов:** оценка прироста точности диагностики при дооснащении установки датчиками обратной связи положения приводов ($CHWC\_VLV$, $OA\_DMPR$).
7. **Доменная адаптация к реальным объектам (CSIRO AHU9):** перенос симуляционных моделей на телеметрию эксплуатируемого коммерческого здания через аффинную калибровку ($C2$) и коррекцию систематического климатического сдвига ($C1$).

### Границы системы (Что намеренно не входит в рамки дипломного прототипа):
- Прямое автоматическое управление приводами здания (система функционирует строго как аналитический советчик оператора BMS / FDD Decision Support System).
- Многоагентные системы генеративного LLM-управления или тяжелые 3D-двойники (BIM/IFC), избыточные для математического решения задачи FDD при ограниченной наблюдаемости.
- Выдача окончательных физических диагнозов причин поломок на реальном здании CSIRO без предварительного дообучения классификатора дефектов (`Domain Guard: LOCALLY_EVALUATED: REGRESSION_ONLY`).

## 2. Архитектура программных компонентов

Система построена по сервисно-ориентированной модульной трехзвенной архитектуре:

```
[ Пользователь / Браузер ] (1440x900, 1280x800)
       │
       ▼ HTTP / REST (JSON)
[ Frontend: React 18 + Vite + Tailwind CSS + Apache ECharts ]
  ├── Мониторинг AHU (мнемосхема, плеер, качество данных)
  ├── Диагностика (карточки решений, физические свидетельства, Ground Truth)
  └── Исследования (Risk-Coverage, 5 профилей наблюдаемости, рекомендатель, CSIRO)
       │
       ▼ REST API (Порт 8050)
[ Backend: FastAPI (Python 3.11) + Pydantic v2 + SQLAlchemy 2.0 ]
  ├── Endpoints: /api/telemetry, /api/diagnostics/*, /api/sensors/recommend, /api/adaptation/*
  ├── Services: TelemetryService, DiagnosticsService, RecommenderService, AdaptationService
  └── Security: Domain Guard, Path Traversal Sanitizer, Upload Validator
       │
       ├── Метаданные (сценарии, каналы, запуски, события) ──► [ SQLite / PostgreSQL ]
       ├── Временные ряды телеметрии (Snappy compressed)  ──► [ Apache Parquet Store ]
       └── ML Артефакты (LightGBM, Ridge, Calibrators)   ──► [ models/*.joblib + JSON ]
```

## 3. Модель данных и хранилище

1. **Реляционная база данных (SQLAlchemy):**
   - `Dataset`: происхождение данных (`SIMULATED_BENCHMARK`, `SYNTHETIC_DEMO`, `REAL_FIELD_BMS`, `USER_UPLOADED`), хэш SHA-256, объем, метаданные лицензии;
   - `Scenario`: временной срез работы установки, интервал дат, статус часового пояса, путь к parquet-файлу, истинная метка (`source_fault_label`);
   - `Sensor`: канонические каналы AHU (30 стандартных тегов ASHRAE/LBNL), единицы измерения, принадлежность к профилю Basic;
   - `DataQualityEvent`: зарегистрированные аномалии качества (разрывы, дубли, замирания сигнала, нарушение монотонности);
   - `DiagnosticEvent`: результат работы диагностических правил и моделей, уровень уверенности, статус свидетельств.

2. **Колоночное хранилище телеметрии (Parquet):**
   - Файлы хранятся в `data/processed/{scenario_id}_{filename}.parquet`.
   - Использование PyArrow обеспечивает скорость выборки произвольного канала за год работы установки (< 50 мс) без загрузки остальных колонок в оперативную память.

## 4. Защита домена и обработка ошибок (Domain Guard & Security)

1. **Доменный барьер (Domain Guard):**
   - Модели `vs-sa-temp-v2` и классификаторы дефектов сертифицированы для симулятора LBNL (`SIMULATED_BENCHMARK`).
   - При выборе полевой телеметрии (`REAL_FIELD_BMS`) система блокирует генерацию необоснованных диагнозов, активируя статус `LOCALLY_EVALUATED: REGRESSION_ONLY`.
   - При выборе синтетических или пользовательских файлов (`USER_UPLOADED`) система возвращает статус `OUT_OF_DOMAIN_UNVALIDATED`.
2. **Безопасность импорта:**
   - Строгая санитизация имен файлов `Path(filename).name` исключает атаки типа Path Traversal и Zip Slip.
   - Защита эндпоинта `/api/adaptation/runs/{run_id}`: принудительная изоляция внутри директории `research/runs/` с отклонением некорректных путей (HTTP 400).
   - Лимит веб-загрузки (50 МБ) с кодом HTTP 413 для защиты от исчерпания памяти.
