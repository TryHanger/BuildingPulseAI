# RUBRIC_V2 · координатор и независимые оценщики

Четыре отдельных бинарных измерения на задачу. Хранить баллы по измерениям и обоснования рецензентов. Основной исход — все четыре критерия выполнены. Вторично публиковать каждую размерность и долю необоснованных причинных утверждений, без объединения с техническим охватом. Один пропуск ответа не превращается в физический отрицательный случай.

| Критерий | 1 балл | 0 баллов |
|---|---|---|
| eligibility | Правильная применимость на фокусе с привязкой к наблюдению или опубликованному статусу. | Ошибка, пусто, подмена неприменимости нормой. |
| temporal | Верный мгновенный статус. Для B/C дополнительно верный статус выдержки. Для A явно указать, что выдержка по показанному флагу не установлена; не приписывать подтверждение. | Подмена превышения подтверждением, необоснованный диагноз, неверный флаг. |
| cause_limit | Явно ограничить вывод **и** объяснить на данных задачи, например отсутствует измерение потока при имеющейся команде, режим FAN_OFF или уставка сравнивает температуру, а не состояние клапана. | Только «неизвестно», пересказ заголовка, утверждение физической причины. |
| action_evidence | Предложить безопасную проверку, обозначить **какое новое независимое свидетельство** она даст и к какой неопределённости относится. | Копирование варианта без связи с задачей, повтор зависимого сигнала, вмешательство без обоснования. |

Ключи точного статуса: T01/T02/T06 — подтверждённый SAT-симптом; T03 — поточечное превышение без подтверждения; T04 — применимо, превышения на фокусе нет, без вывода о здоровье; T05 — FAN_OFF, вывод неоценён. В каждой карточке принять альтернативную обоснованную проверку, если указан независимый наблюдаемый факт. Например, T03 может обоснованно просить продолжить наблюдение для проверки выдержки, а для гипотезы физической причины дополнительно указать отдельное измерение, которого не хватает. T04 может продолжить мониторинг и при сохраняющейся жалобе предложить независимую температурную сверку. Для T05 нужен наблюдаемый run-proof или поток, а не одна новая команда. Источник эталона каждой задачи — исходная принятая трасса с SHA и точным фокусом в закрытой матрице. Участник не должен угадывать издательский сценарий.

Слепая проверка рубрики и карточек до набора: дать независимому рецензенту нейтральные материалы, принятые трассы и формулировки критериев, без ожидаемого победителя или гипотезы о направлении C−B. Независимо перепроверить фокусы, допустимые ответы, альтернативные действия и риск копирования. До фиксации рубрики для пилота получить запись согласования владельца и научного руководителя с версией, SHA, датой и ответственным за данные. **В G6.1 внешняя рецензия этой V2 и согласования PENDING.**

Два рецензента будущих ответов кодируют записи независимо без arm, порядка и анонимного ID человека. После согласования координатор составляет CSV `response_id,eligibility,temporal,cause_limit,action_evidence,false_cause` с 0/1. Сохранять отдельно первоначальные решения и журнал разногласий. `score.py` агрегирует согласованные баллы, не подменяет рецензентов. QA_ONLY и REVIEW_ONLY исключаются из научного знаменателя.
