# Предварительная проверка Stage14 · APAR Rule 3

Этот протокол ограничен проверкой источника по опубликованному регламенту Stage14. Полный отдельный файл задания `TASK_SINGLE_AGENT_S_BP_ML_FIELD_APAR_GATE_14.md` пока недоступен. Числовое сравнение и окончательная приёмка Stage14 по этому протоколу не проводятся.

## Правило и входы

Физический ориентир — APAR Rule 3 для режима нагрева, таблица 2.1 NISTIR 6994. При запросе клапана около максимума и достаточном отставании фактической SAT от активной уставки притока возникает свидетельство нехватки нагрева. Формально `abs(u_hc - 1) <= ε_hc` и `T_sat_setpoint - T_sat >= ε_t`. Это проверка несогласованности температурного управления, которая не локализует клапан или насос. [NISTIR 6994](https://nvlpubs.nist.gov/nistpubs/Legacy/IR/nistir6994.pdf).

- `signal__required_value__heater_valve` — запрос BAS 0–100%, для формулы переводится в долю. Положение штока не наблюдается.
- `air_temperature__real_value__supply_air_outlet` — опубликованная измеренная SAT в °C. Независимость от вмешательства не аттестована.
- `air_temperature__required_value__supply_air_outlet` — точное нативное имя, ожидаемое для кандидата в активную уставку SAT. Даже при наличии требуется доказать активность. `air_temperature__required_value__exahust_air_inlet`, пределы `air_temperature__min/max__supply_air_outlet` и уставка жидкости не подходят.
- `logic__required_value__heater`, `logic__required_value__chiller`, `logic__real_value__fan_fresh_air` — только наблюдаемый контекст BAS 1/0/1. Истинный режим и исполнение требуют отдельного подтверждения.
- Нативный `fault` исключён из входов. Расписание используется только для исключения дат по контексту.

Разделы 2.1–2.3 Nehasil et al. описывают адаптированные проверки и семантические теги, но не раскрывают необходимый конфиг этого правила для каждой AHU. Раздел 3.2 описывает запись вмешательств в BAS. Модель публикации не воспроизводится. `APAR_INSPIRED_NOT_PAPER_REPLICATION`. [Nehasil et al. 2021](https://doi.org/10.1016/j.enbuild.2021.110781).

## Порог и этапы

Пороги `ε_hc` и `ε_t` закреплены как `UNSET_NO_PUBLISHER_SITE_CALIBRATION`. В NISTIR 6994 пороги зависят от площадки и неопределённости. Здесь запрещено оценивать численный порог из уже просмотренных Stage12/13 температур или считать отсутствие порога нулём. Наивный SAT-drop остаётся неоценённым, пока оба gate не пройдут.

Gate A проверяет наличие и допустимость ролей, нативную шкалу и пригодность источника. При отсутствии активной уставки или аттестации режима Gate A получает STOP. Gate B сравнения не запускается при STOP. Аудит кандидатов перечисляет все нативные тики, по одной строке на непрерывный дневной интервал [first_tick,end), с указанием 300 секунд и всех общих причин недопуска. Не исключать дни на основании workbook fault/no fault. Для контекста сравнения отдельно отметить дату любого известного вмешательства и ±1 календарный день по Stage12. Независимое здоровье не аттестуется. Ни одна температура, метрика сравнения, FDD-тревога или оценка точности не выводится.
