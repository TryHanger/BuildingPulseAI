# BP-16 · руководство ведущего

**Статус — техническая подготовка пилота.** Участников ещё не было. Экран предназначен для контролируемой локальной сессии. [Протокол](PROTOCOL_16.md) · [ключ для ведущего](SCORING_KEY_16.md) · [база BP-15](../../../REVIEW_INDEX_15.md) · [технический отчёт](TEST_RESULT_16.md)

## Подготовка

1. Наберите инженеров, работающих с вентиляцией, или студентов инженерного профиля, знакомых с AHU и BAS. До первой сессии согласуйте процедуру с ответственным руководителем. Участие добровольное. Сообщите, что будет сохранён случайный номер сеанса, набор ответов и длительности, без имён или контактов. Участник может прервать сеанс и удалить ответы до выгрузки. При отказе после выгрузки ведущий удаляет указанный локальный файл до обезличенной сводки.
2. Зафиксируйте релиз кода и материалы, подготовьте однотипные рабочие места, размер экрана и одинаковые инструкции. Не раздавайте ссылки на GitHub, ключ, предыдущие выводы и исходный экран BP-15. Участников, уже знакомых с ответами на эти четыре задачи, учитывайте отдельно на этапе набора. Выполняйте сессии по одному, без подсказок и внешнего поиска.
3. Подготовьте два перемешанных блока по восемь назначений до начала набора. Зафиксируйте локально seed и список, выдавайте следующий код после согласия. Подробности баланса, неполных блоков и прерываний указаны в [протоколе](PROTOCOL_16.md).

```sh
mkdir -p "$HOME/bp16-local"
python research/evidence/bp16/pilot_data.py assign --blocks 2 --seed "$PILOT_SEED" \
  > "$HOME/bp16-local/allocation.json"
```

Назначьте `PILOT_SEED` целое число до запуска команды. Храните последовательность у ведущего.

## Запуск на рабочем месте

Из корня репозитория в Python-окружении установите закреплённые зависимости. Используйте отдельную временную SQLite, каталог данных и подписанный по SHA-256 реестр Stage02. Скопированные источники сверх уже присутствующих в Git для пилота не нужны.

```sh
python -m pip install -r backend/requirements-audit-linux-py312.lock
npm --prefix frontend ci
VITE_BP16_PILOT=1 npm --prefix frontend run build

PILOT_SCRATCH="$(mktemp -d)"
export DATA_ROOT="$PILOT_SCRATCH/data"
export DATABASE_URL="sqlite:///$PILOT_SCRATCH/pilot.db"
export VIRTUAL_SENSOR_RESEARCH_DIR="$PWD/research/ml_repro_02/registry"
export VIRTUAL_SENSOR_RESEARCH_MANIFEST_SHA256=359afbe1d3022e64c52ec5e1d916bb731a8c4c45aef9a835d0c9ab6ba73c0734
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 18075
```

```sh
# Второй терминал
VITE_API_URL=http://127.0.0.1:18075 npm --prefix frontend run preview -- --host 127.0.0.1 --port 15197
```

Для назначенного кода 1 откройте `http://127.0.0.1:15197/research/engineer-decision-pilot?sequence=1`, для остальных подставьте назначенный код. Пользовательский экран работает на loopback при явном флаге сборки. Каждый запуск открывайте в отдельном контексте браузера. Не обновляйте страницу посреди сеанса. При обновлении ответы в памяти теряются. Используйте локальную копию интерфейса без сетевых переходов.

## Текст перед первым заданием

> В каждом из четырёх исторических случаев выберите решение, допустимый вывод и следующее измерение. Используйте только информацию на экране. Когда будете готовы, откройте следующее задание. Время учитывается с появления материалов до подтверждения всех трёх ответов. Отказ от физического вывода может быть инженерным решением. Если вкладку пришлось скрыть или источник недоступен, сообщите ведущему. В конце сохраните локальный файл.

Не разъясняйте значения конкретных строк и не обсуждайте ответы до завершения пилота. Для стандартизации ответов используйте один и тот же текст для обеих групп показа.

## Сохранение и разбор

После четырёх подтверждений нажмите «Сохранить ответы» и убедитесь, что в локальном каталоге появился один `bp16-response-*.json`. Файл содержит только версию протокола, базовый SHA, случайный UUID сессии, назначение, позиции и коды ответов, исторический статус, длительности и флаги прерывания. Выгрузка выполняется браузером как файл, сервер не получает ответы. Повторная выгрузка имеет тот же UUID, поэтому проверка офлайн отвергает дубликаты. Файлы ответов и сводки держите вне репозитория, с доступом у ведущего. Не связывайте UUID с именем. Для выбытий и технических сбоев ведите только агрегированные счётчики по кодам назначения. Не заполняйте пропущенные сессии вручную.

```sh
python research/evidence/bp16/pilot_data.py score "$HOME"/bp16-local/bp16-response-*.json \
  > "$HOME/bp16-local/scored.json"
```

Ключ применяется после завершения сессий. Для отчёта опишите поток набора, завершённые сессии, знаменатели по случаю и условию, парные разности и исключения из анализа времени. Отдельно укажите знакомство с AHU у набранной группы на агрегированном уровне, если оно известно из критерия отбора. Данные одного исторического прогона или площадки не удваивают число независимых источников. До реального пилота публикуются только технические проверки.
