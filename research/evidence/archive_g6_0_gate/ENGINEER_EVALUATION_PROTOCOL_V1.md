# ENGINEER_EVALUATION_PROTOCOL_V1 · G6.0

**Статус NOT_EXECUTED.** Девять ретроспективных задач отобраны до тестирования инженеров. Набор и автор рубрики уже знакомы с исходами. Участники будущей оценки могут быть ослеплены относительно сценариев и гипотезы, но признаки интерфейса видимы. Этическое согласование, набор и одобрение владельцем/аудитором предшествуют запуску. В G6.0 участников и оценок полезности нет.

## Материалы и подготовка

`SOURCE_TASK_MATRIX.csv` — закрытая таблица координатора и оценщиков. Шесть CORE_G36 T01–T06 и три TRANSFER_ONLY T07–T09. Хэши исходных файлов, исходные часы, фокус, ожидаемые статусы, допустимые действия и пределы зафиксированы. Для шестёрки из принятой трассы G5.7 взять указанный интервал и точку фокуса включительно. Будущие относительно фокуса отсчёты скрыты. Окна используют 5 min или 1 min с сохранением реальной сетки. Действующий BASIC не пересчитывается на обрезанном окне. Квитанции LBNL и RBC приложены. Демонстрационные fixtures не входят в задания.

Подготовить общий читаемый снимок данных из замороженных источников. Для каждого отсчёта поля: относительное время к фокусу, SAT, SAT SP, MAT, fan status, cooling/heating command и доступный контекст OAT/OWB с нативными единицами. Неприменимые поля явно отсутствуют. A берёт eligibility и мгновенный флаг из принятого результата. B/C используют один замороженный объект с `basic_reason`, `basic_point_exceeds`, `basic_confirmed_timeline`, статусами качества, интервалом и denominators. Для 1wk и 5wk на фокусах использовать timeline подтверждение. Перед сессией проверить соответствие accepted traces, равенство B/C по полям диагностики и отсутствие меток в файлах, атрибутах, сетевых запросах и названиях. Локальный стимул может быть статическим снимком, чтобы все три представления имели одинаковые базовые элементы, разрешение, легенду и задержку. Живая страница G36 с названиями сценариев не годится как ослеплённый стимул без фильтра.

Всем состояниям показываются одинаковые наблюдения и вопросы. Из материалов участника исключить имя CSV, URL, историю этапа, ground truth, признак сценария и ответы. Только C получает метку происхождения в рамках изучаемого контраста, без сценария. Использовать нейтральные обозначения экранов. Ни одна основная карточка не содержит oracle. Для T06 после завершения **всех основных задач** показать отдельную одинаковую всем участникам выдержку G5.3 EXTRA_SIMULATED при 16366800 s и спросить, является ли значение самостоятельным физическим подтверждением. Предварительный ответ не меняется. Вторичный ответ T06 фиксируется вне основного контраста. Для T07–T09 использовать отдельный блок с нативными статусами, без попытки пересчитать G36; результаты описываются по карточке.

## Сессия и порядок

Ориентир на пилот — 12 инженеров или специалистов по BAS/наладке. Это логистическая цель, без заявления о мощности. Фиксировать опыт, знакомство с BuildingPulse и знакомство с исходниками; ранее знакомых с этими карточками оставить в явно отдельной описательной группе. Стандартное обучение по нейтральному примеру на чтение экрана без оценочного исхода. Обратная связь об ответах только после всех задач.

Блочное назначение из шести последовательных анонимных ID. Для шести порядков экранов ABC, ACB, BAC, BCA, CAB, CBA независимо задать по одной строке расписания. В каждом блоке перемешать назначение ID этим строкам. Разбить core на фиксированные тройки T01–T03 и T04–T06. Каждую тройку отдельно перемешать и сопоставить её три задачи трём слотам экранов. У каждой строки порядок экранов свой, а получившаяся разбивка задач между A/B/C одинаковая по позициям во всём блоке. В каждом слоте два задания, их порядок независимо перемешивается для участника. В итоге каждый участник проходит каждую задачу ровно один раз, у каждого экрана две задачи, каждая задача в полном блоке появляется дважды в каждом состоянии. Перед набором фиксируются версия генератора и приватный seed. После завершения публикуются seed и обезличенное расписание. В неполном блоке баланс описывается фактическими знаменателями.

Проверенный генератор включён в пакет. Запуск для контрольного плана: `python verify_design.py /original --seed 20261108 --blocks 2`. Пример seed предназначен для воспроизведения алгоритма. Для реального набора хранится другой закрытый seed.

Таймер стартует после готовности материала и останавливается на первом финальном ответе, предел 180 s на задачу. Отдельно логируются прерывание, недоступность экрана и тайм-аут. В основном анализе тайм-аут оставляет время правосторонне цензурированным и ответ отсутствующим. Повтор после технического сбоя только до раскрытия ответов, с записью причины. Собираются анонимный ID, задача, состояние, порядок, статус симптома, возможность атрибуции, обоснование, следующая проверка, время и статус завершения. Версии стимулов и seed сохраняются с хэшами. Ответы не редактируются после отправки.

## Рубрика и метрики

Два оценщика размечают ответы независимо, без ID участника, условия и порядка. По возможности маскировать цитату подписи интерфейса без удаления смысла. Разногласия разрешаются по заранее закреплённой рубрике, сохраняются обе исходные оценки и причина согласования. До пилота координатор проверяет ключи с принятыми артефактами; отдельный экспертный аудит допустим как описательная проверка формулировок. Числа об участниках или выигрыше нельзя подставлять из экспертной проверки.

| Метрика | Условие и знаменатель |
|---|---|
| Primary · accuracy of justified conclusions | Один балл за верный статус фокуса и обоснованную границу атрибуции, иначе ноль. Отдельно доля от всех назначенных core и чувствительность среди завершённых. Неполные ответы показывать отдельно. Главный контраст C−B в процентных пунктах с парой долей по каждому участнику и разбивкой по задачам. |
| False-cause attribution | Доля завершённых ответов с утверждением установленного компонента без независимых доказательств. Дополнительно число относительно назначенных. Условная гипотеза с проверяемой альтернативой допустима. |
| Abstention appropriateness | Доля завершённых заданий, где участник верно различает «причина не установлена», «метод не оценивал» и «оценивал, подтверждения нет». Указывать знаменатели и пропуски по состояниям. У всех карточек v1 причина неподдержана, поэтому специфичность воздержания на причинно подтверждённых случаях не оценивается. |
| Action selection | Один балл за выполнимую проверку с объяснением, какое свидетельство она добавит. Доля от завершённых, число и доля от назначенных рядом. Примеры в матрице, равнозначные безопасные проверки принимаются. |
| Time-to-decision | Медиана и межквартильный диапазон завершённых ответов по состояниям, число тайм-аутов и технических потерь отдельно. Показать парные медианы по участникам с обоими наблюдениями. Не присваивать 180 s завершённому ответу при цензурировании. |
| Технический охват | APPLICABLE / все исходные отсчёты по прогонам, B и C одинаковы. Отдельно доля завершённых человеческих решений. |

Например, для T02/T03 допустимы проверка независимого SAT-референса, валидности режима, поступления воды, доли наружного воздуха или синхронного воздушного баланса при явной связи с неопределённостью. Ответ не обязан угадать скрытый ярлык. Для T03 нужно различить поточечное превышение и ещё не подтверждённый симптом. Для T05 достаточны распознавание FAN_OFF/неоценённого состояния и предложение проверить режим. Для T08 необходима проверка единицы и шкалы до интерпретации. Фразы «клапан сломан», «утечка доказана», «нет проблемы, потому что нет подтверждения при OFF» не засчитываются. A может обоснованно сказать, что из мгновенной тревоги нельзя заключить о выдержке; это честное воздержание по доступной информации. При оценке статуса дать полный балл, если правильно названо наблюдаемое превышение и явно указано, что состояние подтверждения недоступно в A; для B/C требуется верный флаг подтверждения, включая его отсутствие на T03. Отдельно сохранять статус ответа и точную рубрику, чтобы не смешать доступность факта с корректностью трактовки.

Участник — единица описания человеческих решений, задача — повторяющийся блок. Результаты по 5wk и 1wk не трактуются как независимые физические испытания. При 12 участниках публикуются числители, знаменатели, распределение парных различий и зависимость от порядка/задачи без подтверждающего теста гипотезы или обещания статистической мощности. Протокол пересматривается до сбора данных при изменении источника, интерфейса, эталона или обнаружении утечки сценария.
