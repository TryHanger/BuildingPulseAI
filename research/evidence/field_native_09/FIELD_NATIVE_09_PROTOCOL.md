## Rules, inputs and outcomes

Only naive Time, logic__real_value__fan_fresh_air (supply), logic__real_value__fan_exahust_air (exhaust), logic__required_value__heater and logic__required_value__chiller enter rule computation. The fan statuses are BAS_REPORTED_STATUS with UNKNOWN_PHYSICAL_LINEAGE; heating/cooling requests are commands and regime proxies. The signal__required_value__fan_* tags are drive commands and are excluded. Worksheet fault, all schedule metadata, notes, event IDs and ground truth are excluded from rule inputs. Only a separate evaluation layer joins a window to precomputed tick evidence. Missing/non-binary inputs are unknown. No browser/client scored payload.

A marks an evaluable tick as BAS supply off when supply status equals 0, otherwise reported on. One valid tick can report state but a window needs two adjacent valid ticks before it receives a state summary. A supply on-to-off change requires a directly preceding on tick and two consecutive off ticks. B is applicable per tick only with both fan statuses and heating request 1/cooling request 0. It reports paired on, paired off or disagreement. A B change requires a directly preceding applicable paired-on tick, followed by two consecutive applicable paired-off ticks. Two native ticks establish repeated observations at least 300 s apart, never continuity between ticks. Two immediately preceding warm paired-on ticks are required for the B pre-window baseline and for control selection. A baseline of two off ticks is a pre-existing off state, never a new intervention onset. A missing value or mode mismatch breaks consecutive evidence. Paired or supply off without the requisite baseline/transition can be reported descriptively and must not count as a new change. Preserve first off sample, second confirmation sample and onset bound (last observed on, first observed off], along with relative offsets to logged start. Where no observed change, timing is unknown. Report longest contiguous source span as last minus first sample and report sampled counts. No rule output is a confirmed fault or an alert.

Window states are OBSERVED, NOT_APPLICABLE or INSUFFICIENT_DATA, with ABSTAIN for unavailable conclusions. If only missing statuses, report ABSTAIN even when request context is absent. Report coverage separately for supply, exhaust, simultaneous known, four synchronized fan pairs, requests and heat context. If a possible publisher override is documented for a selected interval, report it as publisher annotation with physical state UNKNOWN_PHYSICAL_LINEAGE, never inferred measured motion.
