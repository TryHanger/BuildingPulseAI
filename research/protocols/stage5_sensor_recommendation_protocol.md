## 1. Научная гипотеза H3

> **Формулировка H3:** Выбор дополнительного диагностического канала телеметрии на основе эмпирической валидационной оценки ценности измерения ($\Delta \text{SelectiveRisk}$ при контролируемом целевом охвате $c$) обеспечивает превосходство над случайным выбором (Random Baseline) и фиксированным инженерным выбором (Fixed Baseline) по снижению риска ошибочной локализации на отложенных независимых сценариях неисправностей при одинаковом бюджете в **один дополнительный канал**.

### Допустимость отрицательного результата
Если на отложенных сценариях рекомендатель, обученный на валидации, не превосходит фиксированный выбор (например, эвристику «всегда добавлять $CHWC\_VLV$») или демонстрирует нестабильность ранжирования, гипотеза H3 признаётся **НЕ ПОДТВЕРЖДЁННОЙ (`NOT_SUPPORTED`)** или **ОГРАНИЧЕННОЙ (`INCONCLUSIVE`)**. Подгонка весов или ретроспективная смена критериев после оценки теста категорически запрещены.

## 2. Множество кандидатов и ограничения бюджета

1. **Бюджет:** Строго **1 дополнительный канал** ($\text{budget} = 1$).
2. **Множество кандидатов для профиля `BASIC` ($J$):**
   - $j_1 = \text{CHWC\_VLV}$ (датчик положения штока клапана охлаждения, feedback, 0–1);
   - $j_2 = \text{OA\_DMPR}$ (датчик угла открытия заслонки наружного воздуха, feedback, 0–1).
   *(Примечание: канал `RA_DMPR` в симуляции LBNL жёстко кинематически связан с `OA_DMPR` через противолежащую тягу, поэтому в MVP-1 исключён во избежание дублирования).*
3. **Реальность каналов:** Рекомендуются только каналы, фактически существующие в схеме и поддерживаемые физической конфигурацией AHU.

---

## 3. Математический критерий выбора и функция ценности

Для каждого кандидата $j \in J$:
1. Моделируется расширение профиля: $p \rightarrow p + j$.
2. На валидационном наборе данных вычисляется селективный риск при фиксированном целевом охвате $c$:
   $$R_p(c) = \text{SelectiveRisk}(p, c)$$
   $$R_{p+j}(c) = \text{SelectiveRisk}(p+j, c)$$
3. **Эмпирическая ценность канала (Empirical Channel Value):**
   $$V_j(c) = R_p(c) - R_{p+j}(c)$$
4. **Фиксированный целевой охват:** $c = 0.60$ (физический предел базового профиля Basic). Если при $c = 0.60$ охват недостижим из-за структуры дефекта, используется резервная точка $c = 0.50$.
5. **Правило выбора (Recommendation Policy):**
   $$j^* = \arg\max_{j \in J} V_j(c)$$
   при условии $V_{j^*}(c) > 0$. Если для всех кандидатов $V_j(c) \le 0$ либо разница статистически неразличима ($|V_{j_1} - V_{j_2}| < 0.01$), система возвращает статус `NO_RELIABLE_RECOMMENDATION`.

## 4. Разделение данных и защита от утечки (Data Leakage Guards)

### 4.1. Схема независимых групп
- **Train Set (Обучение классификаторов семейств дефектов):**
  - Дни 1–9 сценариев: `FAULT_FREE` (норма), `coi_bias_-4`, `coi_bias_4`, `coi_stuck_025`, `coi_stuck_075`, `damper_stuck_025`, `damper_stuck_100`.
- **Validation Set (Выбор рекомендованного канала и калибровка $V_j$):**
  - Дни 10–11 обучающих сценариев (независимый временной блок нормы и дефектов обучения).
  - На этом этапе разрешён расчет моделей профилей `+VALVE` и `+DAMPER` для сравнения их риска.
- **Held-out Test Set (Оценка эффективности H3):**
  - Дни 12–14 независимых сценариев с иными интенсивностями: `coi_bias_-2`, `coi_bias_2`, `coi_stuck_010`, `coi_stuck_050`, `damper_stuck_010`, `damper_stuck_075`.

### 4.2. Инвариант анти-утечки (Test Leakage Barrier)
1. **В момент принятия решения о рекомендации на тесте:**
   - Алгоритм видит ТОЛЬКО каналы текущего профиля `BASIC`.
   - Значения каналов `CHWC_VLV` и `OA_DMPR` на тестовом сценарии **заблокированы и недоступны**.
   - Метка Ground Truth (`source_fault_label`) на тесте полностью скрыта.
2. **После выбора измерения:**
   - Для валидации гипотезы H3 в экспериментальном раннере открывается **только один выбранный канал $j^*$**.
   - Пересчитывается прогноз модели профиля $p + j^*$ и замеряется истинный выигрыш $\Delta R_{\text{held-out}}$.

## 5. Три конкурирующие стратегии для проверки H3

1. **Random Strategy:** случайный выбор кандидата из $J$ с равной вероятностью $p = 0.5$. Оценивается по среднему и дисперсии на 5 фиксированных random seeds: `42, 123, 456, 789, 999`.
2. **Fixed Strategy:** фиксированное априорное инженерное правило — «Всегда дооснащать клапан охлаждения $CHWC\_VLV$».
3. **Validation-Based Strategy:** выбор на основе максимизации $V_j(c)$ на валидационных данных.
4. *(Контрольный потолок — Oracle Upper Bound):* выбор канала, который ретроспективно максимизирует F1 на конкретном тестовом файле. Явно помечается как **недостижимый теоретический оптимум (Infeasible Upper Bound)**, запрещённый к использованию в продакшене.

---

## 6. Негативный контроль (Negative Control)

Проводится прогон рекомендателя на данных с **перетасованными валидационными метками (Permuted/Shuffled Labels)**.
- **Инвариант:** метод не должен показывать превосходство на псевдослучайных метках. Если алгоритм на случайных метках побеждает обоснованный физический выбор, ранжирование признаётся артефактом утечки или шума.

---

## 7. Условия отказа от рекомендации (`NO_RELIABLE_RECOMMENDATION`)

Рекомендатель обязан явно вернуть отказ с описанием причины при следующих условиях:
1. `OUT_OF_DOMAIN`: сценарий не относится к проверенному домену (например, Synthetic Demo без адаптации).
2. `INSUFFICIENT_EXCITATION`: привод не совершал движений (статическая команда), невозможно оценить механическое следование.
3. `CANDIDATES_EXHAUSTED`: все доступные каналы уже включены в активный профиль.
4. `NO_POSITIVE_GAIN`: $V_j(c) \le 0$ для всех кандидатов.
5. `AMBIGUOUS_TIE`: кандидаты показывают неразличимый прирост при высокой дисперсии.
6. `SENSOR_FAULT_SUSPECTED`: датчик кандидата имеет статус stuck или пропуски в сырых данных.
