# G1 — PRE-INTEGRATION_GATE

Ни один исследовательский пакет не импортирован в BuildingPulse и ни один кандидат не запускался. Проверки ниже основаны на статическом чтении upstream и на инвентаре панели. Версии идентифицируют прочитанные материалы и кандидатов, которые требуют отдельного решения перед интеграцией. Полные Git SHA находятся в [upstream-refs](logs/upstream-refs.txt).

[PyPI release](https://pypi.org/project/open-fdd/4.4.9/) · [Исходники rules на теге](https://github.com/bbartling/open-fdd/tree/32a6d4479abed81f9d6d0ff426260cc8ad8e30e2/open_fdd/rules)

| Rule / входы | Предположение, отказ и проверка без интеграции | Gate |

| `AHU-SATDEV`, SAT и SAT SP, fan proof | У upstream по умолчанию `abs(ΔT)>5°F`, 600 s подтверждения, gate fan-on с 600 s startup delay. LBNL SAT может не регулироваться при открытии economizer менее 100%. Сверить знак/Δ°F/Δ°C, окно без разрыва, режим, invalid SAT, startup, переходы и календарное cycling. Есть здоровая симуляция для контроля; GT для причины по SAT отсутствует. | CONDITIONAL только predicate при дополнительном режиме, с локальными тестами и без root-cause claim |
| `AHU-DUCTHI`, static + SP | В BASIC есть обе колонки, однако raw pressure показывает конфликт масштаба. Oracle разрешает отдельную pressure-on эвристику. Сверить единицы и источник перед применением | STOP до QA |
| `AHU-SIMUL`, heat/cool valve; `FC5` heating commanded | Нет нужной heating команды/позиции в 30 точках | STOP, использовать SAT tracking |
| `ECON-1/2/3`, OA damper и температура/погодные роли | Пороговая модель отличается от 33.8/60 °F LBNL. `ECON-3` требует внешнюю dry bulb и dewpoint/RH и использует 60–72 °F. Команда заслонки не подставляется вместо положения. | STOP, native control sequence в G2 |
| `ECON-4`, MAT/RAT/OAT и fan | Оценка OA fraction по смешению требует режима, подходящих точек и достаточной ΔT. Заявленный минимум 21% не следует из 10% открытия заслонки; отсутствие расхода BASIC исключает валидацию. | STOP для G3 MVP |

**Rust/DataFusion platform — STOP.** Ветка платформы описывала Rust central, SQL/DataFusion и отдельный React/edge pipeline, тогда как актуальная upstream документация сообщает о переходе production historian/rules на Timescale SQL. HEAD при опросе `4c9eead4a91529446ff812d204410a56ae868bd3`, MIT. Эти runtime системы имеют собственную модель источников и развёртывание. Ни одна не нужна для проверки SAT на нашем CSV. Перед любым переносом правил pin revision и проверить actual inputs, units, gating, outputs и license; альтернативы — собственные узкие rules и проверка маленьким Python oracle. [Репозиторий Open-FDD](https://github.com/bbartling/open-fdd) · [Архитектура historian](https://bbartling.github.io/open-fdd/architecture/storage-and-datafusion.html)
