Разрешены только доказуемо необходимые исправления воспроизводимости, сериализации, текста и расчёта/публикации метрик. Если обнаружится ошибка, влияющая на метрики, сохрани исходные артефакты, опиши изменение в `CHANGELOG`, выпусти новый машинный результат и объясни разницу. Никакого тихого исправления истории.
2. Все 10 событий AHU-10 — `TEST_EXPOSED_FORENSIC_REANALYSIS`, **не blind и не новое независимое подтверждение**. AHU-10 и AHU-9 — установки одного объекта CSIRO; RBC-Nesbitt — другое здание, но его `CCV_FBK` не эквивалентен CSIRO `CCV_CMD`.
3. Никаких Stage 8D, Active Probing, Kalman, N4SID, дополнительной оптимизации Ridge/Fusion. Не изменяй production backend/frontend Stages 1–7.1, не запускай сторонние LLM/делегатов, не выполняй git commit/push/merge/deploy.

5. Наука важнее «красивого процента»: сохраняй отрицательные результаты, высокий FAR, цензурирование и несопоставимость каналов.

### Gate B — целостность исходной разметки и времён

- На выбранных 33 датах воспроизводи ожидаемые **3199 уникальных временных точек** 5-минутной рабочей сетки, 0 повторных timestamps, 0 `NaT`; ни одна календарная точка не оценивается дважды из-за разных экспериментов того же дня.
- Глобальную `in_any_experiment` создавай из **всех 103 зарегистрированных экспериментов AHU-10**, по реальному пересечению интервалов (не только по дате начала), с 30-минутным washout после окончания. Проверяй интервальные пересечения train/val со всеми fault-окнами и washout, включая события, начавшиеся в другой день. Покажи отдельную опциональную чувствительность к pre-fault embargo без изменения основной исторической метрики.
- Контрольный известный срез: **873 train points без зарегистрированных fault/washout**, **1861 чистая нормальная рабочая точка** в совокупной опубликованной метрике, по **485** точек в каждом чистом сезонном наборе (зима/лето/весна), **406** нормальных точек на днях испытаний. Объясни, какие категории исключены/включены и почему суммы согласуются.
- Сезонный FAR должен вычисляться **только** на сезонных нормальных днях, без добавления аварийных дней другого сезона. Зафиксируй явный календарный список дат для каждого среза.
- Проверяй для каждого инцидента `official_fault_start`, `first_observed_timestamp`, `first_alarm_time`, `alarm_already_active_before_fault`, `new_alarm_onset_time`, `latency_minutes` и `left_censored`.

**Критерий B:** tests-invariants и независимый скрипт заново подтверждают размеры, дедупликацию, глобальные маски и отсутствие fault/normal противоречий. Если изменился числитель/знаменатель — STOP и честное расследование, а не ручное восстановление прежнего процента.

### Gate C — единый канонический контракт научных метрик

Сделай **одну** функцию расчёта, которую использует JSON, CSV, Markdown, summary и финальное сообщение. Не дублируй ручные формулы или числовые утверждения в разных местах. Экспортируй **целые числители и знаменатели**, проценты вычисляй из них.

- `legacy_any_alarm_recall` — тревога внутри зарегистрированного fault-window, независимо от возникновения до fault; не называть физическим обнаружением неисправности.
- `post_observation_alarm_all_10` — новая тревога после начала наблюдения, включая left-censored, с явным названием.
- `new_onset_observable_7` — первичная метрика новых onset на **7 событиях с наблюдаемым началом**; отдельно перечисли **3 left-censored: ID 176, 194, 322**. Нельзя трактовать их как наблюдение момента неисправности.
- Контрольные ожидаемые результаты в текущем экспорте: M1 τ=3 **4/7**; M2 τ=4 **2/7**; M3 τ=3 **4/7**. Общие 5/10, 3/10, 5/10 отображай только с корректной квалификацией.
- `normal_FAR = FP_minutes / eligible_clean_normal_minutes`, false alarm episodes/8h — с календарной сегментацией, не сливать через остановки/разрывы. Обязательно показывай normal/fault coverage, OOD/INVALID/ABSTAINED и режимные срезы. При `eligible_clean_normal_minutes=0`: **FAR=null и false_episodes_per_8h=null**, статус `NOT_EVALUABLE_ZERO_COVERAGE`, а не 0%.
- `latency` только из наблюдаемой и валидной временной шкалы, без NaN; стандартный JSON `allow_nan=False`, неопределённые значения `null`.
- Проверки известных предыдущих экспортов, а **не числа для подгонки**: для M2 local τ=4 суммарный FAR **750/1861=40,30%**; летом **45,36%**. Для M1 τ=3 суммарный FAR **979/1861=52,61%**. Пересчитай самостоятельно из pointwise CSV. При отличии не «фиксируй» данные под цифру: останавливайся, выясняй причину и сохраняй сравнение old/new.
- `MA_TEMP==SA_TEMP` — дублирование BMS-каналов, не доказательство отсутствия аппаратного датчика. `RBC-Nesbitt CCV_FBK → CSIRO CCV_CMD` и `MA_TEMP → SA_TEMP` — **`NOT_COMPARABLE`**, не «успешный zero-shot» даже при низком FAR.

**Критерий C:** все значения в финальном отчёте извлекаются из одного машинного манифеста, а тест проверяет их автоматическую парность (без ручных 29,24/41,75 при фактических 40,30).

### Gate D — прозрачное происхождение моделей, σ и порогов

- **Существующие τ=3.00 и τ=4.00 — фиксированные исследовательские пороги**, а не эмпирический p99/p99.5. Приведи обе вещи отдельно: используемые пороги и диагностику training distribution.

- Протокол сохраняй в архиве **как исторический**; приложи `SCIENTIFIC_CORRIGENDUM.md` с указанием `SUPERSEDED` формулировок о blind/percentile selection и ссылкой на фактический код. Не переписывай pre-registration задним числом.

**Критерий D:** manifest содержит `model_artifact_hash`, train dates, training feature order, semantic target, raw signal lineage, sigma formula, fixed thresholds, p99/p99.5 diagnostics и TEST_EXPOSED.
