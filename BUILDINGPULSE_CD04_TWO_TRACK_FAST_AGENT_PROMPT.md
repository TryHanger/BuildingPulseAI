1. Сохранить и хэшировать исторические CD01–CD03. Никаких изменений старых результатов, порогов, ярлыков и production Stages 1–7.1.

Создать `research/cd04/REGISTER.md`: цель двух дорожек, физические пары неисправностей, units/lineage, алгоритмы, одинаковый false-alarm/coverage budget, отрицательные контроли, строго раздельные даты или сценарии. Исследуемые старые CSIRO/Nesbitt сценарии считать DEVELOPMENT-KNOWN / TEST-EXPOSED. Никаких заявлений о слепой внешней валидации.
3. Установить критерии: **new alarm onset в первые 60 минут** с исключением продолжающихся предаварийных тревог; FAR <= 5% одновременно с false episodes/8h <= 2 и явно указанными знаменателями; normal and fault fan-on coverage >=90%; scheduled coverage >=80% в каждой популяции и в каждом событии; 0/0 -> `null NOT_EVALUABLE`. Сравнивать at matched eligibility and budget. Калибровка только по независимой норме, параметры заморожены до test.

## Track A — Field evidence procurement: NIST IBAL
Источник: официальный публичный каталог NIST https://www.nist.gov/el/beed/intelligent-buildings-agents-project/data/database; dictionary https://www.nist.gov/el/beed/intelligent-buildings-agents-project/data/data-dictionary; экспериментальный dashboard https://ibal.nist.gov/experiments; проекты/код https://github.com/usnistgov/IBA-Project.
- Проверить, можно ли действительно экспортировать **один синхронный CSV** из одного экспериментального запуска со связкой `v2_pos_c`, `v2_pos_fb`, соответствующим гидравлическим/воздушным каналом и, при необходимости, `ahu1_out_rtd` (или релевантный SAT). Зафиксировать physical topology: клапан V2 должен относиться именно к исследуемому coil и AHU; не предполагать этого по похожим названиям. Найти точные внешние отметки fault on/off, вид fault, режим охлаждения/отопления, диапазон, калибровку и показание независимого reference. Использовать dashboard только если документация это позволяет, не генерировать фиктивные тесты.
- В первую очередь искать существующие экспериментальные интервалы двух различимых причин (actuator travel loss vs controlled SAT bias) **на одной физической установке**. Если такой пары нет, зафиксировать точный `NOT_EVALUABLE_MISSING_LABELS` и отдельно рассмотреть документированную heating bypass leak vs sensor offset как другую, отдельно предрегистрированную пару. Не подменять один тип неисправности другим.
- Для каждого файла: official URL/version, SHA256, date timezone, cadence, sensor lineage, command/pre-proxy vs override vs measured feedback, calibration, uncertainty, missingness, fault provenance. До получения корректной пары — не тренировать модель и не просматривать fault residuals. Ветки покупки/поиска можно делать параллельно с симуляцией.

## Track B — Simulation-only mechanistic discrimination, LBNL SD-AHU
- Использовать имеющийся **модельный** LBNL Single-Duct AHU с известными injected model state и controller command, **без претензии на независимую полевую проверку**. Изучить структуру и исходную семантику `CHWC_VLV_DM` / `CHWC_VLV`, а также температур/сценариев прежде, чем строить признаки. Значение, принудительно фиксированное инъекцией, считать потенциально `INJECTION_OBSERVABLE`. Нельзя использовать ground truth или override target при выборе модели, если в реальном BMS он недоступен.
- Разработать минимальную **двухклассовую** задачу различения: actuator effectiveness/stuck vs additive controlled-SAT sensor bias. Если LBNL не содержит независимо симулированного sensor-bias сценария той же топологии, явно отметить `MISSING_FAULT_PAIR` и допустить только заранее фиксированное альтернативное *synthetic counterfactual* в отдельном симуляторе, не изображая его настоящим measured data. Для synthetic сценариев обеспечить известные plant/controller equations, noise, actuator saturation, weather nuisance и проверить аналитическое предсказание о неидентифицируемости.
- На одинаковых датах/режимах сравнить `SAT only`, `SAT+upstream command`, `+ independently modeled achieved travel`, `+ independent flow or same-section SAT reference` и два **негативных контроля**: (1) математический дубликат SAT либо command и (2) пост-proxy override value. Отдельно сообщить rank/lowest singular value after nuisance projection, noise-relative separability, event-level confusion, false episodes/8h, alarm delay, coverage. Rank increase **сам по себе** не доказывает статистическую диагностику; инъекционный канал **сам по себе** не является полевой валидацией.
- Не развивать deep models, N4SID/Kalman или новые сложные алгоритмы. Разрешены только линейная алгебра, физически обоснованные остатки, простой rule-based baseline, bootstrap by independent events (если достаточно событий).

## Предохранители против ошибок CD01–CD03
- Глобальная, уникальная timestamp сетка и OR-маска **всех** известных fault событий до выбора нормальных минут; washout; >1 event per day без дублирования. Timestamp valid non-null monotonic, correct physical cadence and unit conversions. HHMM (e.g. 2355) не является количеством минут.
- Отдельно onset after verified fault, already-active alarm, renewed alarm after reset, left-censored faults; no alarm before intervention as successful physical detection. Per-event physical coverage separate from conditional fan-on coverage.
- Все научные таблицы генерировать из одного `RESULTS.json`; исходные счётчики обязательны. `NaN/Inf`, нулевые знаменатели, OOD, алиасинг/повторный сенсор, пост-инъекционные колонки — fail-closed. Code tests должны проверять реальные CSV и реальные timestamps, не только готовые JSON. Отдельные regression/negative tests обязательно должны падать после умышленной порчи input/labels.
- Нет подтверждённых физических датчиков или fault windows — `NOT_EVALUABLE`, а не красивая численная симуляция с ярлыком field result.
