# BuildingPulse AI — правило компактных ZIP от единого агента S

## Базовое решение
Отныне для обычной итерации присылать **COMPACT REVIEW ZIP**: исходный код всех затронутых модулей, новые/изменённые тесты, OpenAPI, версии зависимостей, отчёты/логи и критичные небольшие фикстуры. **Не** присылать каждый раз те же неизменённые годовые CSV, большие Parquet, БД, модели, nested prior ZIP, node_modules и виртуальные окружения.

При этом для независимой воспроизводимости нельзя прислать только patch без исходного кода: нужен как минимум полный актуальный снимок изменённых модулей, файлы зависимостей и зафиксированная основа для восстановления.

## Обязательные файлы каждой сдачи

1. `CHANGELOG.md`: что и почему изменилось, что осталось открытым, новые решения, совместимость.
2. `BASELINE.json`: sha256 предыдущего утверждённого полного архива/коммита, версия API, версия схемы БД, релиз исходного LBNL.
3. `SOURCE_MANIFEST.tsv`: полный список относительных путей + SHA-256 + размер; отдельный признак included / omitted / changed.
4. `PATCH.patch`: текстовый diff для удобства, но не вместо изменённого кода.
5. `backend/`, `frontend/src/`, `contracts/`, затронутые `research/`, `scripts/`, `tests/`, конфигурации, `package-lock.json`/`requirements*.txt` и Docker-конфигурация.
6. `EVIDENCE/`: результаты unit/contract/Playwright, HTTP-json, скриншоты новых или затронутых экранов, stdout/stderr и environment versions.
7. `README_REPRODUCE.md`: способы запуска в изолированном scratch, какие тесты не удалось провести и почему.
8. `SHA256SUMS.txt`: контрольные суммы именно **включённых** файлов; проверять при отправке.

## Исключать при неизменности

- `data/raw/*`, `data/processed/*`, `buildingpulse.db`, большие сохранённые модели и обучающие артефакты.
- `node_modules`, `.venv`, Python кэш, `frontend/dist`, временные файлы.
- Повторно вложенные ранее переданные архивы и исторические логи, если они уже были в утверждённом пакете и записаны в BASELINE.
- Первичные научные статьи/публикации, если переданы ранее и сохранились в Library с ссылкой и хэшем.

**Если raw/processed/SQLite изменились:** не скрывать изменения. Приложить новый файл (или отдельный `DATA_DELTA.zip`), актуальную схему, миграцию, проверку целостности и описание восстановления; при изменениях большого CSV допускается отдельный пакет данных, но это **новая версия источника** и требует научного gate. SQLite лучше заменять миграцией и фикстурами, не передачей живой рабочей БД.

## Два типа пакетов

- **Частый COMPACT (обычно 3–20 МБ):** удобен для аудита изменений, сравнения кода, типизации и небольших тестов. Если отсутствуют данные, строго маркировать `REQUIRES_BASELINE_DATA` — нельзя заявлять fully standalone run.
- **Периодический FULL CHECKPOINT:** после большого gate или если база/данные изменились. Содержит всё необходимое для автономного воспроизведения, кроме секретов. Разрешён больший размер; архивация по SHA и без повторного включения других ZIP.

## Запреты

- Нельзя ради уменьшения ZIP убирать изменённые тесты, сам код, схемы, requirements/lock или данные, без которых **новое** поведение нельзя проверить.
- Нельзя использовать пути `../` в архиве или симлинки наружу.
- Не утверждать `PASS` для тестов, которые запускались только на предыдущем снапшоте или в иной среде.
- Не включать `.env` с паролями, токены, private keys, user information.
- По-прежнему один агент S, ни commit, ни push, ни deploy без разрешения владельца.

## Этот конкретный RC2

Исходный `BUILDINGPULSE_G0_G1_RC2_REVIEW.zip` весит около 208 MiB, из них примерно 192 MiB zip-size приходится на папку `data/`. Для следующего типового ревью полный повтор этой папки не нужен, так как она уже присутствует в данном утверждаемом полном источнике. Сохранять её sha256 и baseline reference обязательно.
