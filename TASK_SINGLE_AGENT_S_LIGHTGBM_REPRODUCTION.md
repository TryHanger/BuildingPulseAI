**Три результата должны быть строго раздельными:**

**Не заявляй заранее**, что LightGBM лучше PCA: в статье для **SD-AHU PCA имеет AUC=1.0 по всем сценариям**, а LightGBM на SA +2 °C =0.9992. Дополнительная ценность LightGBM — сенсорный рейтинг и логика интерпретации; для **FCU**, который не входит в первоначальный GATE, публикация сообщает выигрыш относительно PCA. AUC — не accuracy и не вероятность причины.

## 2. Замороженный протокол воспроизведения — PAPER_FULL_REPRO

Реализуй публикацию **с отдельными тестами для каждого шага**:

- Разделение healthy: первые 80% рабочих (`SYS_CTL >= 1`) минут по времени — обучение, последние 20% — валидация; оценка fault и healthy производится на одних календарных датах в последних 20%, как в статье. Не делай random split по минутам.
- Входные признаки для каждой цели: BRICK-derived neighborhood + `hour`, `month`, `day_of_week`, `occupancy` по методике статьи. Зафиксируй список фактических полей, единицы, алиасы, константы, зависимости от команд/feedback. НЕ заменяй его нашей прежней произвольной четырёхканальной регрессией.
- LightGBM `n_estimators=300`, `max_depth=6`, `learning_rate=0.05`, `subsample=0.8`, `colsample_bytree=0.8`, `random_state=42`, `min_child_samples=50`; документируй версию LightGBM и фактическую активность subsampling (`subsample_freq`/bagging). Не добавляй собственные параметры как будто их установили авторы.
- Для каждого target: абсолютный остаток `|y - yhat|`; `mu` и `sigma` вычисляются **по абсолютным остаткам healthy validation**, а не по signed остаткам и не по fault. `z=(abs_error-mu)/sigma`; случай `sigma` около нуля обрабатывать явно и фиксировать.
- Для каждого дня: **среднее** z по минутам рабочего режима для target; системный дневной score — максимум по target. Для фиксированного порога `daily_z > 3` рассчитать confusion matrix, precision/recall, FPR, охват и false-positive days. ROC-AUC считать **по дневным scores**, не по каждой минуте. Не переводить `z>3` в «99.7% гарантированно правильных диагнозов».
- Isolation: **медиана суточных scores** каждого датчика по сценарию, ranking и разница rank1-rank2. Ранг «подозрительного датчика» — не доказательство физической причины и не вероятность fault.
- Discrimination: `Damper_MAE=MAE(OA_DMPR_DM, OA_DMPR)`, `Valve_MAE=MAE(CHWC_VLV_DM, CHWC_VLV)`. **Только в FULL**, потому что в BASIC actual positions отсутствуют. Наличие модельного feedback в симуляторе — не доказательство установленного датчика на реальном AHU.
- Проведи 10 seeds (0–9) **после воспроизведения seed=42**, отдельно от основной таблицы, при наличии ресурсов. Не расходуй время на бессмысленный гиперпараметрический поиск.

**Опорные авторские проверки:** SD-AHU SA+2 °C AUC 0.9992, остальные 11 сценариев в таблице (включая healthy comparator) — в статье большинство AUC=1.0; SA+2 °C recall при z=3 примерно 0.833; validation RMSE SA_TEMP 0.1516 °F. Если результат другой — сохраняй точный результат, расследуй расхождение по pipeline; **запрещено подбирать пороги/признаки по fault-test, чтобы получить числа статьи**. Эти значения являются ориентирами, не критерием, разрешающим скрытую подгонку.

**Важный методологический дефект оригинального протокола:** healthy validation используется для оценки `mu/sigma` **и** как negative class при ROC. Сохрани эту логику в PAPER_FULL_REPRO (для честности к источнику), но явно опиши возможный optimistic bias; исправление проверяй только в отдельном `STRICT_HOLDOUT`.

## 3. Baselines и сравнение — не делать некорректных выводов

Разработай и сравни на одинаковых календарных днях:

1. **LightGBM+BRICK (paper)**: все 8 сенсоров и published feature neighborhoods, полный режим.
2. **PCA-paper:** максимально восстанови оригинальную постановку PCA авторов по документу; если точная настройка не опубликована — укажи `PCA_REIMPLEMENTED` с выбранными до теста параметрами. Не приписывай ей идентичность исходному коду.
3. **Ridge+same-feature-neighborhood:** простая регрессионная база по тем же target и features, той же train/calendar-mask, той же residual aggregation.
4. **PCA-input-matched (fair):** отдельная PCA на одном и том же разрешённом наборе входов с явно описанной стратегией residual; не выдавать PCA-paper и PCA-fair за одну модель.
5. **SAT setpoint threshold:** традиционная проверка как ограниченный comparator для masked temperature bias; зафиксировать её слабые стороны заранее.

Для каждого: дневные AUC/precision/recall/FPR, error на исправной валидации, средние/медианные ошибки и разрез по сезонам. Нет F1 по неразмеченным onset. Учитывай зависимость соседних дней: **никаких доверительных интервалов, где 525540 минут трактуются как независимые наблюдения**. Оцени валидность парного сравнения и различие домена заранее.

## 4. Строгая независимая оценка — STRICT_HOLDOUT

Отдельный эксперимент, НЕ «репликация статьи»: фиксируем хронологический healthy split, например 60% train, следующие 20% только calibrate, последние 20% untouched test (на одном сценарии и одной TMY симуляции). Fault scenarios оцениваем на соответствующих датах test. Никакая метка, префикс имени fault-файла, команда периода fault или test-statistics не попадает в train/calibration. Список preprocessing, features, пороги, модели, seeds и отбор цель/каналов фиксируется **до открытия результатов test**.

В отчёте честно раздели:
- `PAPER_FULL_REPRO` (условия авторов);
- `STRICT_HOLDOUT` (наш независимый внутри той же симуляции); 
- `PRODUCT_BASIC` (ограниченная реалистичная панель).

Оценка внешней переносимости на реальное здание НЕ разрешена: других физических установок и подтверждённого независимого benchmark сейчас нет. Дополнительный FCU можно предложить **после** выполнения главного SD-AHU результата, отдельно от задач этого этапа.
