# UI_DECISIONS.md — Архитектурные и дизайнерские решения фронтенда BuildingPulse AI

### 1. Архитектура маршрутизации без тяжелых сторонних зависимостей
- **Решение:** Маршрутизация реализована на уровне корневого компонента `App.tsx` с использованием нативного Browser History API (`window.history.pushState` и прослушивателя события `popstate`).
- **Обоснование:** Сохраняет полную обратную совместимость с имеющимися страницами (`/monitoring`, `/diagnostics`, `/research`), не требует изменения `package.json` или внедрения конфликтующих версий `react-router-dom`, позволяет открывать прямые ссылки вида `/assets/:id`, `/incidents`, `/incidents/:id`.

### 2. Физическая честность мнемосхемы AHU
- **Решение:**
  - Мнемосхема выполнена в виде контрастной 2D SVG-векторной графики промышленного стиля.
  - Каждый канал на схеме привязан строго к определенному `canonical_signal_id` (`OA_TEMP`, `RA_TEMP`, `MA_TEMP`, `SA_TEMP`, `CHWC_VLV_DM`, `OA_DMPR_DM`, `SF_SPD_DM`).
  - При отсутствии физического датчика (например, датчика обратной связи положения штока клапана `CHWC_VLV` в профиле `BASIC` или расходомера воздуха `SA_CFM`) интерфейс явно выводит маркер `[Не установлен в BASIC]` или `[Нет расходомера]`, категорически запрещая дорисовывать фиктивные значения.
  - Канал `SYS_CTL` исключен из отображения как измеримый сигнал базовой автоматизации.
  - Анимация вращения вентилятора активируется **строго при подтвержденном флаге `fan_on = true`**.
  - Стрелки направления воздушного потока отображаются только при работающем вентиляторе; скорость движения не выдумывается без физического расходомера.

### 3. Единый Replay Clock с двойным представлением времени
- **Решение:**
  - Компонент `ReplayClockBar` управляет общим временным курсором телеметрии: кнопки Play/Pause, сброс в начало, переключение скорости (x1, x5, x20) и бегунок-скраббер.
  - Временная метка выводится одновременно в формате **UTC** (для академической точности) и **местном времени** (для инженерного удобства).
  - На панели отображается актуальный режим работы установки (`OFF`, `COOLING`, `ECONOMIZER`, `TRANSITION`, `UNKNOWN`) и индикатор разрыва данных при обнаружении пропусков телеметрии.

### 4. 3 синхронных графика ECharts со связанным курсором
- **Решение:**
  - Графики сгруппированы по физическому смыслу:
    1. **Контур притока:** температура притока (`SA_TEMP`), уставка (`SA_TEMPSPT`), прогноз виртуального датчика (`SA_TEMP_VIRTUAL`) и столбиковая невязка (`RESIDUAL`).
    2. **Команды приводов:** команда охлаждающего клапана (`CHWC_VLV_DM`), команда заслонки (`OA_DMPR_DM`) и полупрозрачная полоса ожидаемого коридора (`CHWC_CORRIDOR`).
    3. **Тепловой баланс:** наружная (`OA_TEMP`), возвратная (`RA_TEMP`) и смешанная (`MA_TEMP`) температуры.
  - Для всех рядов установлен параметр `smooth: false` (категорический запрет на искусственное сглаживание неисправностей).
  - Включен разрыв ночных и нерабочих пауз (`connectNulls: false`) для устранения ложных диагональных прямых.
  - Поддерживается сырой зум колесом мыши (`dataZoom: [{ type: 'inside' }]`) и перемещение курсора кликом по графику.

### 5. Четыре независимые оси статуса в Evidence Inspector
- **Решение:**
  - В соответствии с мастер-планом внедрены 4 независимые оси:
    1. `data_state`: `VALID | DEGRADED | INVALID | UNKNOWN`
    2. `cause_state`: `UNEXPLAINED | AMBIGUOUS | ISOLATED_CONDITIONAL | CONFIRMED_EXTERNALLY`
    3. `model_scope`: `IN_SCOPE | OUT_OF_SCOPE | UNKNOWN`
    4. `ground_truth`: статус изоляции эталона.
  - Категорически запрещено выводить некалиброванные проценты вероятности неисправностей (например, «клапан сломан на 95%») или фиктивную экономию в деньгах.
  - Свидетельства классифицируются строго по трем корзинам: `supporting`, `contradicting`, `missing` (не наблюдаемо в данном профиле).
  - Неисполнимые проверки снабжены кодом блокировки и инструкцией по дооснащению.
  - Рекомендации инженеру берутся исключительно из белого списка регламентных процедур (ручной осмотр, контрольный замер термометром) без вызова автоматических управляющих воздействий.

### 6. Sensor Lab без вычислений на стороне клиента
- **Решение:**
  - Вкладка `Sensor Lab` позволяет инженеру переключать профили наблюдаемости (`BASIC`, `BASIC_PLUS_VALVE`, `BASIC_PLUS_DAMPER`, `FULL`) и видеть актуальную матрицу доступности каждого канала.
  - Клиентский код **не выполняет физического моделирования и инференса** — пересчет выполняется только через запрос к серверу по кнопке «Запросить пересчет на сервере».

### 7. Защитный барьер сопоставимости сценариев (Matched Scenario Pairs Gating)
- **Решение:**
  - Наложение графиков нормального и аварийного режимов разрешено исключительно для валидированных пар с подтвержденным `matched_pair_id` (например, летняя неделя симулятора LBNL с идентичным метеофайлом).
  - Для несопоставимых выборок (например, разные климатические сезоны) отображение блокируется информативным баннером с разъяснением физической некорректности сравнения. Подстановка похожих чисел запрещена.

### 8. Адаптивность для экранов 1440 / 1280 / 1024 / Mobile
- **Решение:**
  - На десктопе 1440px и 1280px схема и инспектор свидетельств отображаются рядом в двухколоночном режиме.
  - На экранах $\le 1024$px и мобильных устройствах (<768px) активируется переключатель вкладок «Мнемосхема AHU» ↔ «Свидетельства и Факты», предотвращая горизонтальную прокрутку и наложение элементов.
